Date: 2026-11-04. This is a source-to-value inventory, not a clinical recommendation or a FHIR adapter. Code stays unchanged. The clinical milestone builds shared small values; resource records and links stay in consumers ([ruling](../decisions/2026-10-30-clinical-milestone-builds-small-values-only.md)).

Repeated instances use one row per resource-relative path and value kind. `[]` means every array member; component codes and extension URLs disambiguate meanings. ## Mapping rules and value gaps

A value **holds** an element only when its contract retains the element's source semantics. `Text`, `SourceText` and `Identifier<Text>` can retain spellings; that alone is partial support for a typed coding, quantity or record. No unit conversion, terminology equivalence, clinical significance or coordinate basis is inferred.

| Key | Present value and exact limit | Missing small value |
| --- | --- | --- |
| G1 | `Concept { id: Option<Curie>, label: Text }` can keep one CURIE and label; `Term` accepts only the closed `Coding` enum. Neither retains an arbitrary FHIR system URI, code, version, display, userSelected, multiple codings and optional text together. `Identifier<Text>` retains an explicit source system URI and code as its authority and native value, without delimiter rewriting; this is partial coded support, not the complete Coding contract. An unstated system stays unstated, and no URI is inferred from a label. | Open `CodeSystem`, `ConceptCode`, `CodedValue`; preserve the source coding independently of any normalized concept. |
| G2 | `WithUnit<FiniteNumber, Text>` retains a finite value and one optional unit string. It has no comparator, unit system/code pair or decimal lexical scale. `Fraction` is only [0,1]; a percent needs an explicit source-aware conversion. Marker `alteration::Decimal` is parser-specific, not the clinical decimal contract. | Precision-preserving `Decimal`, `Unit`, `Quantity`, with a stated comparator and source scale. |
| G3 | `Span0`, `UncertainSpan0` and `Position1` hold genomic coordinates only after the source coordinate convention is checked. They do not hold arbitrary measured low/high bounds, units or reference intervals. | General `Range`, `ReferenceRange`; compose genomic endpoints with an explicit coordinate convention, never reinterpret a generic FHIR Range blindly. |
| G4 | `PartialDate` retains calendar year/month/day precision, not dateTime offset/time, periods, age intervals or anchor-relative dates. `TrialUploadTime` validates a source-specific timestamp and is not the general clinical contract. | `TimePoint`, `TimeSpan`, including precision, timezone and anchored offsets. |
| G5 | `Identifier<T>` retains an authority and native value. `Attribution` describes a source claim. Neither supplies the full shared reference/source/loss value contracts in the clinical ruling. Consumer resource/report envelopes are outside this inventory and are not BioData gaps. | `RecordKey`, `RecordRef`, `RecordSource`, `Loss` and loss kinds. Records remain consumer-owned. |
| G6 | `SourceText`/`Text` retain text; neither marks patient-sensitive leaves or governs their exposure. | `PatientText`. |
| G7 | HGVS, ISCN, gene, accession and star-allele values cover their declared grammars; no HLA allele/GL-string value or observed haplotype phase/copy contract exists. `ClinvarHaplotype` is a publisher's membership record, not a patient HLA call. | Source-preserving HLA allele/GL-string leaf and explicit phase/copy context only if an approved consumer needs it; retain unparsed source with a loss until then. |

These are representation gaps, with high confidence from the source fields and BioData definitions. The proposed names come from the existing clinical ruling except G7, which is a candidate need for PM review. They do not authorize new records, terminology services or clinical interpretation.
