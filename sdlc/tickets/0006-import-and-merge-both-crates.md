# Import both crates and merge them by the reconciliation record

Status: COMPLETE.
Landed: 08d9399cc0a29d36fd48c002ccec57a34df37f09

Milestone: 1

## Outcome

`crates/biodata` holds BioMCP's and the second consumer's crates, merged row by row as `sdlc/designs/2026-10-28-reconciliation.md` says, and both consumers' switch branches pinned to this commit pass their acceptance.

## Why

BioData 1.0 is one crate for both consumers, and BioMCP 1.0 ships on it.

## Proof

- Proof: `make gate` passes with both crates' public tests moved in. `scripts/check-reconciliation.py` finds every item where its row puts it. A property test per ONE item shows that its parser accepts exactly what BioMCP's published schema for it states. BioMCP's PM reports an empty reply diff on its switch branch, with `biodata.*` schemas that differ only by the record's listed optional additions, and the second consumer's PM reports identical output, identical index bytes and no lookup slowdown on its switch branch, both pinned to this ticket's commit.

- PM decision 2026-10-31: a fresh private reviewer in the private test repository classifies every ISCN overlap pair by location. A pair is generic when the matched string is a single fact any writer would spell the same way: a chromosome, a band, a gene symbol, a fusion name such as two symbols joined by `::`, or a normal karyotype. Generic also covers required syntax: empty or whitespace-only strings, JSON Schema vocabulary, and the fixed keywords and type labels the grammar or parser defines (PM decision 2026-10-31, added after the first classification). The overlap check skips empty and whitespace-only strings outright. The reviewer lists each generic string in the private allowlist with its class as the one-line reason, and the PM approves the list. Every other match counts as an imported case, and the developer replaces it with a case written from the grammar rules, adapted from no example, including Rust literals in imported source. A final overlap run on the last candidate commit passes before landing.
- PM decision 2026-10-31: `PartialDate` is the one exception to the exact parser and schema property. The property test states that the parser accepts a subset of the schema, and that the two differ only on dates the calendar rules out, such as 2023-02-29.
- PM decision 2026-10-31: the exact parser and schema property covers field shapes and the scalar grammar the eight narrowings set. The record lists them, the frozen schemas stay unchanged, and one outside-in boundary witness per independent rule shows the parser refuses what the schema accepts. Frozen scalar patterns that admit more than the parser, such as Mane's inline RefSeq and version, `Bound`'s null-only bound and missing maximum, and unbounded LRG zeros, are also parser-only for 1.0 and listed. A post-1.0 ticket tightens them under new schema versions. This closes the audit's scope: further schema review reopens only on a difference a consumer's check reports.
